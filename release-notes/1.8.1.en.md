Keep conversation file changes updating over long sessions

Fixed
- A temporary snapshot timeout no longer permanently stops file-change tracking in the conversation. Later observations can retry while keeping earlier changes.
- Projects that temporarily exceed snapshot size or file-count limits are checked again after a one-minute cooldown instead of remaining disabled until restart.
- A file becoming too large or temporarily unreadable no longer stops tracking other files. The affected file remains listed without Undo until its change is kept.
- Retry file reads during atomic replacement, and preserve normal snapshot completion of edit notifications that lack original content.
- Recovery does not attribute unknown changes made during a snapshot gap to the agent, and preserves safe Undo for other files.
