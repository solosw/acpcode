# ACP Agent 的配置、快速安装与目录复制

## 添加和编辑

**Settings → Agents** 只显示已配置 Agent 的列表。点击 **添加 Agent** 或列表中的 **编辑 Agent**，在弹窗中设置启动命令、JSON 参数数组、环境变量以及 Skills/Rules 目录；保存后生效，取消不会写入配置。删除操作只移除配置，不卸载程序，也不删除用户文件。

在添加弹窗中选择 **ACP 注册表**，可从 [官方 ACP Registry](https://github.com/agentclientprotocol/registry) 搜索 Agent。目录来源为官方公开的 [registry.json](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json)，不是微软插件市场或本地预置的固定列表。

1. 选择 Agent，查看软件包或下载来源、版本、启动命令。
2. 点击 **安装并配置**，检查第三方代码与安装脚本提示并确认。仅浏览和取消确认不会执行安装。
3. 安装完成会自动填入配置，按需补充环境变量，点击 **保存** 加入列表。登录、订阅或 API Key 仍需按对应 Agent 的要求配置。

支持 npm/npx、Python/uvx 和目标操作系统架构的二进制归档。npm 类型需要目标主机已有 Node.js/npm/npx，Python 类型需要 uv；不自动安装系统运行时、不使用 sudo。安装失败会保留弹窗并提供重试或手动配置。二进制安装到目标数据目录的 `acp-agents/`，目录提供 SHA-256 时会校验。

## SSH 远程安装与网络

添加和编辑弹窗均可选择 **配置 / 安装位置**，列表包括已保存、已连接及当前工作区的 SSH 主机。默认跟随当前项目；未列出的 SSH 配置别名可先通过打开远程项目连接。选择 **ACP 注册表** 后，程序复用该主机已有的 BaoCode 远程连接，按远端系统和 CPU 架构生成安装方案。当前远程安装支持 Linux/macOS 的 x64/ARM64 平台，缺少运行时会报错，不回退到本机安装。安装前确认窗口会显示目标主机、来源和启动命令。

远程 npm/uvx 安装可选择：

- **使用 BaoCode 网络设置**（默认）：安装进程通过远端回环临时端口，经现有 SSH 连接访问本机代理中继。中继遵循网络设置的系统/手动代理、直连和绕过规则；不把本机 `127.0.0.1` 代理地址直接交给服务器。两个监听端都仅绑定回环地址，使用每次安装生成的临时认证；上游代理密码只留在本机。代理变量仅传给这次安装进程，不写入远端 shell 配置或全局 npm 配置。成功或失败都会关闭中继和监听端口，转发不可用时明确失败，不改用远端直连。
- **使用服务器自身网络**：npm/uvx 使用远端原有登录环境和网络，不注入 BaoCode 本机代理。

注册表和二进制归档始终在本机按网络设置下载；二进制按远端平台选择，在本机校验和解包后通过 SSH 上传到远端用户数据目录，不在本机执行远端程序。整个过程不关闭 TLS 证书验证；企业代理证书及不遵循标准代理变量的安装脚本仍可能需要单独配置。

启动命令、参数、环境变量和 Skills/Rules 目录按主机分别保存。同一个 Agent 可同时配置本机及多个 SSH 主机；新配置在未配置的主机上启动会提示配置，不会借用其他主机的路径或凭据。旧版未区分主机的手动配置保留原有启动行为，保存主机专属配置后改为隔离。安装和配置保存是两步，取消弹窗不会撤销已经完成的包安装。

**安装代理不等于运行代理。** 安装结束后临时通道关闭，Agent 运行时使用目标主机自己的网络和认证；需要 API Key 或登录时请在对应主机上配置，不会自动上传本机凭据。

## Skills 和 Rules 目录

在 Agent 编辑弹窗中分别设置：

- **Skills 目录**：Agent 原生读取的用户级 Skills 目录。
- **Rules 目录**：接收用户级 Rules 的目录。

点击 **选择文件夹…**：本机使用系统文件夹选择窗口，SSH 目标使用远程文件夹浏览弹窗（可以进入子目录、返回上级并选择当前目录）。取消选择不会更改路径。也可手动输入目标主机路径，或清空不需要的目录。

目录留空表示不复制；支持绝对路径和 `~/`。程序不会根据 Agent 名称猜目录，也不会修改 ACP 启动参数。

## 操作

1. 选择目录并保存 Agent 配置，再打开该 Agent 的编辑弹窗。保存配置不会复制文件。
2. 在弹窗顶部选择本机或目标 SSH 主机；复制使用该主机保存的目录配置。
3. 点击 **Preview skills copy** 或 **Preview rules copy**。
4. 核对实际来源、目标、新增、更新、冲突和过期内容，确认后点击 **Copy**。

这是手动增量复制：打开设置、保存自定义文件或启动 Agent 均不会自动写入目标目录。
本机复制使用本机用户配置；SSH 复制使用所选主机自己的用户配置和目录，不会将本机自定义上传到远端，连接失败也不会回退成本机复制。

## 复制范围

来源配置根目录为该主机的 Claude 用户配置目录，默认 `~/.claude`，遵循现有的配置目录解析（含 `CLAUDE_CONFIG_DIR`）。

### Skills

复制 `<config>/skills` 下包含普通文件 `SKILL.md` 的用户 Skill 文件夹：

```text
<config>/skills/pdf/  →  <skills destination>/pdf/
```

复制完整目录，包括脚本、引用、图片、二进制资源、隐藏资源文件和空目录。
不复制云同步的 `synced/`、隐藏的顶层目录、插件或项目级 Skills。

### Rules

保持原始字节，不合并、不改名、不转换 front matter、不注入 ACP 提示词：

```text
<config>/rules/style.md         → <rules destination>/style.md
<config>/rules/nested/style.md  → <rules destination>/nested/style.md
<config>/CLAUDE.md              → <rules destination>/CLAUDE.md
```

规则目录中的辅助文件也会复制。如果用户 `CLAUDE.md` 与规则目录内的同名路径冲突，预览会报错，不会任选一份覆盖。

**复制完成不等于 Agent 一定加载成功。** 请确认目标 Agent 支持这些路径、文件名和规则语法。
路径条件和 `@...` 等相对引用原样保留，不会自动修复布局变化带来的引用问题。
有些 Agent 需要新建或重启会话才读取新增内容；BaoCode 不会自动终止正在运行的 Agent。

## 冲突和安全边界

- 目标根目录的 `.baocode-customizations.json` 是受管清单，记录来源、类型以及已复制文件的内容和可执行标记摘要。
- 只更新内容和可执行标记都仍与清单一致的受管文件。
- 非受管同名文件即使内容相同，也不会被自动接管或覆盖。
- 受管文件在外部修改后显示冲突；存在冲突时整份预览不能执行。请自行保留、移动或处理冲突内容后重新预览。
- 源文件删除后仅标为过期，目标文件和清单记录保留，不自动清理。
- 拒绝源与目标配置目录重叠、符号链接、特殊文件和越界路径。
- 预览后来源、目标或清单发生变化时，需要重新预览。
- 文件逐个暂存并原子替换，不是整目录事务。中途失败可能已有部分文件完成；成功文件会逐个记录，以便重新预览后继续。
- 复制文件采用仅当前用户可读写的权限，在 POSIX 主机保留必要的可执行能力；不复制所有者、组、ACL 或特殊权限位。
- SSH 主机需具备标准 POSIX 工具 `sh`、`mkdir`、`mktemp`、`chmod` 和 `mv`，不依赖 Python。

更换目标目录或移除 Agent 配置不会删除旧目录中的副本。
